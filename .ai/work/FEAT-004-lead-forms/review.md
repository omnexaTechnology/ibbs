| F4-01 | **major** | `src/components/forms/request-form.tsx:50`, `src/components/forms/call-form.tsx:24` | The `<form>` has no `method`/`action`, only a React `onSubmit`. The forms are server-rendered, so until hydration finishes (these pages load Three.js, so hydration can take seconds on mobile), Enter or a click on "Send" makes the browser send a native **GET** to the current page: `/en/contact?name=…&phone=…&email=…&message=…`. Personal data then ends up in Vercel request logs, browser history and analytics (breaks NFR-002), and the lead is silently lost (page reloads, no error shown). | F4-02 | minor | `src/components/forms/use-lead-form.ts:23-25` (with `:49`, `:66`) | The timing clock restarts **every time `status` becomes `"idle"`**, not only on mount and on "send another". ## Checked and fine

- REQ-009: the write token is read only in `save.ts` (`server-only`), never `NEXT_PUBLIC_`, and absent from client chunks.
- Leads are created as `lead.<uuid>` via `leadDocumentId()` (dotted ID, so anonymous users cannot read them); the test pins the ID format.
- REQ-008/BR-003: save → email → patch. Either step succeeding → 200. Both failing → 502 `delivery_failed`. A failed patch is still a success, and `emailDelivered` stays `false` (the Studio field explains what that means). The patch runs only when both steps succeeded. `visibility: "async"` on create followed by a patch by ID is safe (the mutation is committed before the response).
- NFR-002: logs contain only the step name and `error.name` (tested with PII in error messages). Responses carry only error keys. `pageUrl` holds origin + pathname only (no query string).
- Reply-To is set only from a `z.email()`-validated value. The subject has CR/LF removed, and Resend's JSON API rules out header injection.
- `formType` and `locale` are whitelisted with `z.enum`. Unknown keys are stripped by `z.object`. The honeypot is checked before the schema.
- Arabic-Indic (U+0660–0669) and Eastern Arabic-Indic (U+06F0–06F9) digits are normalized, and `00` becomes `+`.
- EN/AR `forms.*` keys are identical in both files. Error messages are keys, so they are localized on the client, including field errors returned by the server.
- Accessibility: labels tied to inputs with `htmlFor`, `aria-invalid` and `aria-describedby` on errors, focus moves to the first invalid control (client and server errors), the error banner is `role="alert"`, the success panel is `role="status"` and takes focus, the form is `aria-busy` while sending.
- Double submit: the button is disabled while sending, plus a status guard. Implicit submission does not fire while the submit button is disabled.
- "Send another" remounts the form, so fields are empty and errors are cleared.
- RTL: logical classes (`ms-`, `text-start`), email/phone/area forced LTR.
- Honeypot: `aria-hidden` wrapper, `tabIndex={-1}`, `autoComplete="off"`, visually hidden without `display:none`.

## Result
Built (2026-10-27, branch feat/FEAT-004-forms):
- src/lib/validation/lead.ts: zod 4 schema shared with the browser. Error messages are keys (forms.errors.*) so the UI localizes them. Saudi mobile (05x, 5x, 966, +966) and international E.164 (+ or 00 prefix); Arabic-Indic digits accepted and normalized. Required: name, phone, and email or message; the "call" form type needs only a phone.
- src/app/api/leads/route.ts: size limit (413) -> JSON parse -> honeypot (fake success) -> schema (400 with field keys) -> timing check (fake success) -> save to Sanity -> email -> patch emailDelivered. Success if either save or email worked, 502 if both failed. Logs only the step name and error class.
- src/lib/leads/save.ts (write client, lead.<uuid> IDs via leadDocumentId, server-only), notify.ts (recipients from getLeadRecipients(), else LEAD_FALLBACK_EMAIL; Resend), src/emails/new-lead.ts.
- Email template is a plain HTML string builder (.ts, not .tsx): one table with inline styles; @react-email would add many packages for no gain. Message text is HTML-escaped (tested).
- Dependencies added: zod, resend. react-hook-form is NOT added (T-002 uses plain uncontrolled forms + the shared schema, lighter).
- .env.example: RESEND_API_KEY, LEAD_FROM_EMAIL, LEAD_FALLBACK_EMAIL (the real address only as a commented example).
- Tests: src/app/api/leads/route.test.ts (18: success, fallback recipient, email down, Sanity down, both down, no config, patch failure, honeypot x2, too fast, missing timing, invalid, email-or-message, call form, malformed JSON, oversized x2, field too long, no PII in logs) and src/lib/validation/lead.test.ts (22). All mock Sanity and Resend; nothing touches the network.

Assumptions:
- The browser measures the time since the form rendered and sends it as elapsedMs (immune to clock skew). Under 2000 ms or missing = bot (fake success). A non-browser client that omits it gets a fake success, not an error.
- The space type is sent as a key (hq, offices, ...) and stored/emailed as the English label from the design, so the sales team reads one language.
- Phone is stored normalized (digits, leading +, e.g. 0501234567 or +966501234567), not as typed.
- Without LEAD_FROM_EMAIL the sender is Resend test sender onboarding@resend.dev (only delivers to the Resend account owner, matches R1).
- No rate limit in code (T-003 adds the Vercel Firewall rule).
- A Sanity create uses visibility "async" for speed (NFR-001).

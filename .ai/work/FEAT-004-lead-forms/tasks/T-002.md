## Result
Built (2026-10-27):
- src/components/forms/: fields.tsx (TextField, TextAreaField, SelectField, Honeypot: label, aria-invalid, aria-describedby, required marker), form-success.tsx (role=status, takes focus), use-lead-form.ts (shared hook: same zod schema as the server, POST /api/leads, status, focus first invalid field), request-form.tsx (full form + error banner with WhatsApp fallback), contact-form.tsx, project-form.tsx (adds the design heading), call-form.tsx (phone + optional name, quickDone text).
- Plain uncontrolled forms + FormData instead of react-hook-form: the shared schema already does the validation, so the extra dependency was not needed.
- Props: whatsappHref (string or null, from whatsappHref(settings, locale) in lib/contact.ts); null hides the fallback link.
- messages EN/AR: forms.errors.*, forms.spaceTypes.* (the design 8 options), fSelect, callTitle, callHint. Other strings reuse the design T keys (fName, okTitle, okAgain, quickDone, sendWa, ...). callTitle/callHint are for T-003 to use around the call form; unused for now.
- RTL: logical Tailwind classes (ms-, text-start), email/phone inputs forced LTR.
- Tests: src/components/forms/forms.test.tsx, 11 tests (EN and AR required + invalid messages and focus, success + reset, payload locale/pageUrl/formType, delivery failure + WhatsApp link, hidden link, server 400 field errors, project form, call form, honeypot).
- Not wired into any page (T-003). No e2e fixture page added: the repo has no such pattern for components yet and component tests cover the behaviour; T-003 e2e will exercise the real pages.
- Validation: npm run lint clean, tsc clean, vitest 22 files / 218 tests pass, npm run build succeeds with no env.

Assumptions:
- Required stars only on name and phone; email carries the "email or message" rule through its error text.
- Space type select starts on a "Select…" placeholder (design had no empty option; the field is optional).
- Area is a free-text numeric field (inputMode numeric), stored as text like the lead schema.
- Visitors on error can retry in place; their input is kept.
- Not browser-tested in a real browser (no dev server run); visual styling uses existing tokens and is untested against the design.

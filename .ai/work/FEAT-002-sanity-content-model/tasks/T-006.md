## Acceptance criteria
- [x] Anonymous API query for `_type == 'lead'` returns nothing (BR-007, AC-005) — proven on the still PUBLIC dataset thanks to `lead.<uuid>` IDs (details in Result)
- [x] Read token cannot be bundled to the client (server-only import) — `import "server-only"` + unit test + build scan

Protection is server-only use + no site query touching leads + `lead.` IDs for anonymous access. A custom role would be needed to change this (paid plan).

## Result
- Sanity docs (https://www.sanity.io/docs/content-lake/ids, read via `sanity docs read`, 2026-10-26): documents with a `.` in the ID are only accessible to logged-in users or with a token; only root-path IDs are anonymous-readable. CLAIM CONFIRMED by documentation and by test.
- Live test (dataset PUBLIC at the time), `npm run verify:privacy`: created `lead.<uuid>` with the write token, then 8 checks passed: anonymous query by type (api and apicdn hosts): 0 results; anonymous query by exact ID (both hosts): 0 results; anonymous `GET /data/doc/production/<id>`: HTTP 200 with `documents: []`, `omitted: [{reason: "permission"}]`; write token could see it; test lead deleted afterwards (verified gone).
- Build scan: 651 files in `.next/static`: no token names, no token values. Names appear only in server bundles.
- `SANITY_REVALIDATE_SECRET` is empty in `.env.local` (length 0) so the webhook endpoint answers 401 to everything until the user sets it.

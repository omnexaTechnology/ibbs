## Result
Built (all client components unless noted; styles in `src/styles/ui.css`, classes prefixed `ui-`, values from the design CSS):
- `section-heading.tsx` (server component; eyebrow + stripes, title, lead, action slot, stripe-beat on hover), `reveal.tsx`, `hotspot.tsx`, `carousel.tsx`, `counter.tsx`, `accordion.tsx`, `lightbox.tsx`, `gsap-refresh.tsx`.
- Hooks: `use-in-view`, `use-gsap-refresh`, `use-swipe`; `src/lib/gsap.ts` registers GSAP + ScrollTrigger + `useGSAP` from npm (REQ-014). `<GsapRefresh />` is mounted in the locale layout and lazy-imports GSAP, so pages that never use GSAP do not download it. It refreshes ScrollTrigger after each route change and, debounced 150 ms (as in the design), when the page height changes.
- Messages: new `ui` namespace (en + ar): prev/next, slide labels, lightbox labels, scene labels (used by T-002).
- Test helpers: `src/test/dom-mocks.ts` (reduced motion, IntersectionObserver mock).

Decisions and deviations:
- Hotspot (F-09): `HotspotImage` takes the cropped image ratio (`aspect`) and sizes its box to exactly that ratio; the page puts the image in with `fill` + `object-cover`, which cannot crop any further because the ratio matches. Pins are `%` of that box. RTL uses `100 - x`; the layer stays `direction: ltr` as in the design and the tooltip side flips with the mirrored x (design rule `x > 55`). Pins are real buttons, tooltip shows on hover and on keyboard focus (`:focus-within`), linked with `aria-describedby`.
- Reveal: server HTML is always visible (no hidden state without JS). With scroll-driven animations (`animation-timeline: view()`, same ranges as the design: 0-55% / 0-70%) it is pure CSS; otherwise an IntersectionObserver fallback plays the same keyframes. Reduced motion: untouched. No `delay` prop (the design has none for `.rv`).
- Carousel: cross-fade 1.4 s, auto-advance 5 s (the design hero timer), restart of the countdown after any manual change. Added beyond the design: it pauses on hover, on focus inside, when off-screen and when the tab is hidden (WCAG 2.2.2). Arrow keys follow the visual direction (reversed in RTL). Swipe supported. Slides are `inert` unless active. Reduced motion: no auto-advance. There is no separate play/pause button (the design has none); flag for T-010 if the accessibility pass wants one.
- Counter: 2 s ease-out cubic, starts at 35% visibility, once. Final value is in server HTML and in an `sr-only` span; the animated text is `aria-hidden`. Reduced motion shows the end value at once. Formats with `en-US` digits like the design.
- Accordion: single-open (first open by default), heading + button + labelled region, closed panels `inert`, Up/Down/Home/End between questions.
- Lightbox: rendered in a portal on `document.body` (a `.rv` ancestor with a transform would otherwise trap `position: fixed`); Esc, arrows (overlay is always LTR like the design, Left = previous), swipe, Tab trap, scroll lock, focus restored to the opener. Uses a plain `<img>` (eslint exception noted in code) because the URL is already sized by the Sanity CDN and `next/image` has no remote patterns configured yet.
- No routable test page for the primitives; they are covered by component tests (the 3D fixture page in T-002 also shows a few).

Validation: 39 new tests (hotspot RTL math and pins, carousel dots/keyboard/RTL/reduced motion/pause/off-screen, counter end value and once-only, accordion aria and keyboard, lightbox keys/swipe/focus, reveal modes, GSAP refresh on route change and resize); `npm run lint`, `npm run typecheck`, full vitest suite pass (170 tests).

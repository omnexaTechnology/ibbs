## Result
Modules in `src/three/`: `info.ts` (piece names EN/AR, zones, `yawTo`), `materials.ts`, `kit.ts` (`createKit(M)`, all 28 builders typed), `walk-layout.ts`, `models.json` + `models.ts` (lazy `loadModels()`, `modelGroup()`), `renderer.ts`, `dispose.ts`, `loop.ts` (`RenderLoop`), `light-compat.ts`, `scene-types.ts`, `scene-canvas.tsx` (WebGL, loaded only client-side), `scene-root.tsx`, `demo-scene.ts` (template + fixture).

How a scene is written: `export default (ctx: SceneContext) => ({ frame?, resize?, dispose? })` in its own file, mounted with `<SceneRoot load={() => import("@/three/scenes/x")} label fallback={<Image fill .../>} />`. `ctx` gives renderer, scene, camera, `quality`, `reducedMotion`, `invalidate()`, `own(cleanup)`, `createKit()` (materials + kit, disposed automatically).

SceneRoot behaviour: nothing loads until the scene is within 300 px of the viewport (`useInView`); WebGL is probed with a throwaway canvas first, so browsers without WebGL never download Three (fallback + `scenes.stillL` note, REQ-013); the Three chunk is `next/dynamic` with `ssr: false`; frames run only while the canvas is on screen and the tab is visible; unmount disposes handle, scene graph (geometries, materials, textures), kit, renderer and forces context loss; unmount during loading is safe. Context loss shows the fallback. R1: DPR cap 2 (1.5 on touch, 1 on low-end), shadows off and no MSAA on low-end (<= 4 GB or <= 4 cores on touch). Reduced motion: on-demand rendering, one still frame, `ctx.reducedMotion` for scenes. Optional `releaseWhenFar` unmounts a scene far off-screen to free its GL context (off by default; T-010 should decide for the home page, which has several scenes).

Three revision: the design bundles r149, this site uses r186. Handling so r186 renders like the design:
- Colour management: r149 legacy mode used hex colours as authored with sRGB output. `THREE.ColorManagement.enabled = false` (set in `configureThree()`) restores that; textures use `colorSpace = SRGBColorSpace` (was `encoding`); `renderer.outputColorSpace` (was `outputEncoding`).
- Lights: legacy lighting (all intensities x PI) was removed in r155+. Use `legacyIntensity(x)` for ambient/hemisphere/directional. Point lights also changed falloff; `legacyPointLight` / `legacyPointFactor(distance, decay)` match the old curve at 40% of range. Scenes with point lights (process office, 3D build) must be eyeballed.
- `PCFSoftShadowMap` no longer exists; `PCFShadowMap` is used.
- Visual check: the demo scene (desk, chair, sofa, plant) renders plausibly in headless Chromium, but I did not run the design's r149 side by side, so exact brightness parity is unverified; T-004/T-006-T-008 should compare each scene with the design.

Deviations: the canvas is created imperatively inside `SceneCanvas` (not by React) so a force-lost context never gets reused (React Strict Mode safe). Layout fabrics are material names resolved by the scene. The logo texture is `/brand/logo-light.png` (same file as the design logo). Test page: `src/app/[locale]/e2e-fixtures` answers 404 unless built with `E2E_FIXTURES=1`, which `playwright.config.ts` sets for its webServer only; a plain `npm run build` does not enable it.

Validation: 26 new unit tests for 3D (dispose bookkeeping and shared resources, DisposeBag, kit builds every piece and the full walk layout, quality/DPR, light maths, RenderLoop pause/resume/dispose/on-demand, SceneCanvas pause off-screen / dispose on unmount / unmount while loading / unsupported / error / reduced motion, SceneRoot lazy mount / no-WebGL fallback). e2e `e2e/three.spec.ts` (4 tests: canvas mounts and draws, not created while far, no-WebGL fallback, primitives incl. counter and RTL hotspot). Full run on port 3200: lint, typecheck clean; vitest 196 passed (25 files); `npm run build` with no env OK; playwright 76 passed.

## r149 → r186 colour and light compatibility: correct

Checked against the design (`Main.dc.html` 4586-4593: `outputEncoding = sRGBEncoding`, ACES, `PCFSoftShadowMap`) and the r186 sources in `node_modules/three`:
- `ColorManagement.enabled = false` matches r149, where `legacyMode` was on by default: hex colours are not converted to linear. In r186, `convert()` returns early when disabled (ColorManagement.js:47). Texture decoding does not depend on this flag: `WebGLTextures` picks `SRGB8_ALPHA8` from `getTransfer(colorSpace)`. So `texture.colorSpace = SRGBColorSpace` matches the design's `encoding = sRGBEncoding`, and `outputColorSpace = SRGBColorSpace` matches `outputEncoding`. Clear colour and background stay raw hex in both versions.
- Lights: r149 legacy mode multiplied ambient, hemisphere, directional, point and spot intensities by π (`scaleFactor` in WebGLLights). `legacyIntensity = x·π` is exact. `useLegacyLights` was removed in r165, so there is nothing left to switch off. The point-light falloff formulas in `light-compat.ts` match both shaders (r186 `lights_pars_begin` `getDistanceAttenuation`).
- `PCFSoftShadowMap` still exists as a constant in r186, but WebGLShadowMap.js:99-101 warns and falls back to PCF. Using `PCFShadowMap` directly is correct.
- `configureThree()` runs inside `createRenderer`, before `createKit` and before the scene module loads, so every material colour is created with management off.
- Remaining parity risks are listed as B1-10 and B1-11. Brightness parity with the design was never checked side by side. T-002 says this too.

## What is good

- SSR safety: nothing touches `window` or WebGL at import time. `SceneCanvas` is `next/dynamic({ ssr: false })`. `near` is false on the server, so the server HTML and the first client render match.
- Disposal: `DisposeBag` runs LIFO and survives a throw. Unmount releases the scene graph (shared geometries, materials and textures once each, plus background and environment), the kit cache, the logo texture, the renderer and `forceContextLoss`, and disconnects the RO and IO, the visibility listener and the context-loss listener. The context-loss listener is removed before `forceContextLoss`, so unmounting never reports "lost". Unmounting while the scene is loading is handled and tested.
- `RenderLoop`: pauses off-screen and in hidden tabs, clamps `dt`, stops after dispose, and renders on demand under reduced motion. The tests drive it through faked rAF and IO and assert on frame counts, not on implementation details.
- DPR cap of 2 (1.5 on touch) matches the design. Low-end devices get DPR 1, no MSAA, no shadows. WebGL is probed before anything loads; context loss and factory errors show the fallback.
- Carousel, accordion and lightbox follow the WAI-ARIA patterns (inert slides and panels, real buttons, focus trap and restore, scroll lock). Counter puts the final value in server HTML and an sr-only copy. Reveal shows content without JS. The global reduced-motion rule also stops the hotspot rings.
- Tests check behaviour: RTL maths, keyboard, timers, reduced motion, disposal counts, lifecycle races.
